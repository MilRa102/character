# Character — AI-компаньон-шторка для COSMIC

Рабочее название: **Character**. Цель: персонаж в «шторке» сверху экрана, который
следит за системой через D-Bus, слушает обращения и выполняет ограниченный набор действий.
Реагирует эмоциями и анимацией, показывает тултип и/или говорит голосом.

## 1. Принципы

1. **Нативность**: Rust + libcosmic/iced, layer-shell (`zwlr_layer_shell_v1` / `cosmic-panel`-совместимо). Без Electron.
2. **Локальность по умолчанию**: STT, wake-word, TTS и LLM работают локально; облако опционально.
3. **Ограниченные полномочия**: LLM никогда не исполняет произвольные команды — только действия из allowlist.
4. **Событийная модель**: система → события → политика → персонаж. LLM вызывается не на каждое событие.
5. **Деградация**: без LLM/голоса остаётся правило-based реакция + анимация + тултип.

## 2. Компоненты (демоны и процессы)

| Компонент | Роль | Технологии |
|---|---|---|
| `character-ui` | Шторка, рендер персонажа, тултип, анимации | Rust, libcosmic/iced, wlr-layer-shell, Rive/Lottie или спрайты/skeletal |
| `character-core` | Центральный демон: шина событий, FSM состояния, оркестрация | Rust, tokio |
| `character-watch` | Наблюдатель D-Bus: системные и сессионные сигналы | zbus |
| `character-voice` | Wake-word, VAD, STT, TTS | Ollama audio-capable models, Piper; wake-word planned |
| `character-brain` | Диалог и выбор действий (tool calling) | llama.cpp / Ollama (локально), опционально облако |
| `character-actions` | Исполнитель allowlist-действий + подтверждения | Rust, polkit (где нужно) |
| `character-memory` | Короткая/долгая память, настройки, профиль | SQLite |

Связь между процессами: собственный D-Bus-интерфейс `org.character.Core1` (session bus)
или Unix socket + JSON; UI подписывается на состояния.

## 3. Источники событий (D-Bus и не только)

| Источник | Шина / интерфейс | Что даёт |
|---|---|---|
| Уведомления | session: `org.freedesktop.Notifications` (monitor) | Входящие, срочность, приложение |
| Медиа | session: `org.mpris.MediaPlayer2.*` | Играет/пауза, трек |
| Питание | system: UPower `org.freedesktop.UPower` | Заряд, низкий уровень |
| Сеть | system: NetworkManager | Подключение/потеря сети |
| Сессия | system: `logind` | Блокировка, сон, idle |
| Устройства | system: udisks2 / `org.bluez` | USB, Bluetooth |
| Сервисы | system: `systemd1` | Упавшие юниты |
| Окна/фокус | Wayland `ext-foreign-toplevel-list`, `cosmic-toplevel-info` | Активное приложение (контекст) |
| Idle/активность | `ext-idle-notify-v1` | Простой пользователя |
| Журнал | journald (только ошибки/предупреждения) | Сбои |

Слежение за *действиями пользователя* ограничивается метаданными (активное приложение,
idle). Содержимое экрана/ввода **не** читается без явного включения.

## 4. Поток обработки

```
Событие → Нормализация → Политика (правила, троттлинг, приоритет)
  ├─ тривиальное → мгновенная эмоция + тултип (без LLM)
  └─ требует осмысления → brain (LLM) → ответ + tool call?
                                   └─ actions (allowlist, confirm) → результат → эмоция/тултип/голос
Голос: wake-word → VAD → STT → brain → (actions) → TTS + эмоция
```

## 5. Состояния персонажа (FSM)

`hidden` → `peek` (выглядывает) → `idle` → `listening` → `thinking` → `speaking` / `acting` → `idle`.
Оверлеи эмоций: `happy`, `curious`, `worried`, `sleepy`, `alert`, `confused`, `proud`.
Приоритет: `alert` > `listening` > `acting` > `speaking` > фоновые реакции. Шторка сворачивается после
таймаута; при fullscreen-приложении — режим «не беспокоить» (только критичное).

## 6. Действия (allowlist)

Каждое действие — декларативный манифест: имя, схема аргументов, уровень риска, нужно ли подтверждение.

| Уровень | Примеры | Подтверждение |
|---|---|---|
| 0 — чтение | время, заряд, статус сети, текущий трек | нет |
| 1 — безопасные | громкость, яркость, play/pause, DND, открыть приложение из списка, таймер | нет |
| 2 — заметные | закрыть окно, переключить Wi-Fi/BT, создать заметку/напоминание | голос/кнопка в тултипе |
| 3 — опасные | сон/выключение, удаление, сетевые изменения, установка пакетов | явное подтверждение + polkit |
| ✗ — запрещено | произвольный shell, sudo, чтение файлов вне списка | никогда |

Правила: LLM возвращает только структурированный вызов (`action_id` + args); валидация по JSON-схеме;
журнал всех вызовов; «kill switch» (хоткей/кнопка) мгновенно глушит микрофон и действия.

## 7. Приватность и безопасность

- Микрофон: индикатор активности всегда виден; в MVP-2 он открывается только в явном режиме
  Voice и только на время удержания push-to-talk. Аудио хранится во временном WAV с правами
  владельца, передаётся настроенному Ollama audio endpoint и удаляется после транскрипции;
  wake-word пока не реализован.
- Режимы: `off`, `events-only` (без микрофона), `voice`.
- Облачный LLM по умолчанию выключен; в него уходит только минимальный контекст, с фильтрацией.
- Защита от prompt injection: текст уведомлений/окон помечается как *недоверенные данные*, действия
  уровней 2–3 не выполняются на основании недоверенного контента без подтверждения пользователя.
- Конфиг и allowlist хранятся в `~/.config/character/`, действия исполняются от пользователя, без root.

## 8. Конфигурация

```
~/.config/character/
  config.toml        # режимы, модели, голос, горячие клавиши
  actions.d/*.toml   # манифесты действий (allowlist)
  persona.toml       # характер, тон, имя, реакции
  skins/<name>/      # анимации и ассеты персонажа
```

## 9. Дорожная карта

1. **MVP-0 — реализован**: отдельная шторка (layer-shell) + статичный Fen с эмоциями
   `curious`, `happy`, `worried`, `sleepy` + тултип; ручные демонстрационные события.
   Открытие/сворачивание кнопкой, автосворачивание через 12 секунд вне шторки; микрофон выключен.
2. **MVP-1**: `character-watch` (notifications, UPower, NM, MPRIS) + правила реакций без LLM.
3. **MVP-2 — в работе**: первый срез — push-to-talk → локальный STT → диалог с локальным LLM
   → текстовый ответ и опциональный локальный TTS; wake-word и действия уровней 0–1 пока не реализованы.
4. **MVP-3**: allowlist-движок, подтверждения, журнал, kill switch.
5. **v1**: система скинов, память, контекст активного окна, упаковка (AUR PKGBUILD), интеграция в COSMIC-настройки.

## 10. Открытые вопросы

- Для MVP-0 выбран отдельный layer-shell surface; вариант апплета в `cosmic-panel` пока не реализуется.
- Формат анимации: Rive (state machines) против спрайтов/Spine. Нужна проверка поддержки в Rust.
- Выбор локальной модели под tool calling при ограничениях по VRAM/CPU.
- Доступ к фокусу окон в COSMIC: нужные протоколы (`cosmic-toplevel-info`) и их стабильность.
